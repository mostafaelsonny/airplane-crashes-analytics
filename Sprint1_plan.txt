Sprint 1 — Foundation & End-to-End Proof of Concept
1. Sprint Overview
Sprint Goal
Establish the project foundation, prepare the development environment, inspect and define the historical aviation accident dataset, and implement a working End-to-End Proof of Concept connecting Python, Kafka, Apache NiFi, Apache Spark Structured Streaming, and PostgreSQL.

ببساطة، هدفنا إننا نثبت إن كل المكونات الأساسية بتتكلم مع بعضها وبتنقل البيانات بشكل صحيح.
Sprint Duration
Item	Value
Duration	6 Working Days
Daily Availability	3–4 Hours
Total Hours / Member	18–24 Hours
Team Size	6
Total Team Capacity	108–144 Hours


Sprint Scope
الحاجات اللي لازم ننجزها:
1. تحديد مصدر البيانات وتنزيل الـ Dataset.
2. فحص البيانات وفهم Structure بتاعتها.
3. اعتماد Data Contract موحد.
4. تجهيز Docker Environment.
5. تشغيل Kafka وإنشاء Topics.
6. إنشاء Python Producer يرسل Historical Records.
7. إنشاء NiFi Flow يقرأ البيانات وينفذ ETL مبدئي.
8. نشر البيانات المعالجة إلى Kafka.
9. إنشاء Spark Structured Streaming Application.
10. قراءة البيانات من Kafka باستخدام Spark.
11. تخزين البيانات في PostgreSQL باستخدام foreachBatch.
12. تنفيذ End-to-End Integration Test.
13. تجهيز Documentation أساسية للمكونات.
Out of Scope
الحاجات دي مش مطلوبة في Sprint 1:
- تنفيذ جميع التحليلات النهائية.
- بناء Dashboard كاملة.
- تنفيذ Geographic Analytics.
- بناء Advanced Analytics.
- بناء Authentication أو User Management.
- تحسين الأداء على نطاق Production.
- تنفيذ Monitoring System متكامل.
- التعامل مع جميع أنواع أخطاء البيانات المحتملة بشكل نهائي.

نقطة مهمة بخصوص Data Source
الـ NTSB بتوفر Aviation Accident Dataset رسميًا، والبيانات متاحة في ملفات Microsoft Access، وتشمل بيانات حوادث الطيران التاريخية.

الملف الأساسي الحالي avall.zip يغطي بيانات 2008 حتى الوقت الحالي، وهناك ملفات تاريخية للفترات السابقة. والـ Dataset بتتحدث دوريًا. data.ntsb.gov

المصادر الرسمية:
- NTSB Aviation Data Download Directory
- NTSB Accident Data Documentation
لكن فيه قرار تقني لازم يتنفذ في Day 1:

ملفات NTSB مش بالضرورة CSV واحد بسيط؛ هي قواعد بيانات Access تحتوي على جداول وعلاقات. لذلك أول مهمة لمسؤول البيانات هي فحص الـ Schema وتحديد الجداول والحقول اللازمة.

مش هنفترض إن كل البيانات موجودة في Table واحدة.
